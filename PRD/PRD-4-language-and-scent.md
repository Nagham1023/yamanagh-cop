# PRD 4 — Language and Scent

Status: **Done, including Revision 1.** Originally built per `TODO4.md`'s §0–§12 checklist (see "Built & verified" below); a direct re-read of the book (ch. 4.2–4.4) surfaced three real deviations in the scent model, corrected per `TODO4-revision.md` and "Revision 1" below (see that section's own "Built & verified" for the revision's close-out). Design Question 1's original answer is superseded, not deleted — see the note inline.

`PLAN.md` §5 calls this "the step change, and the most delicate layer in the project." It owns the fatal rule (27) this whole codebase has been carrying scaffolding around since PRD 2, and it's the first layer where the cop genuinely loses perfect information — everything before this reasoned about a target position it was simply handed.

## Build

- **Close the PRD 2 carve-out (rule 26/27).** Remove `tools/mcp_server.py`'s `receive_position(col, row)` tool and `tools/mcp_client.py`'s `send_position`, replace with `receive_hint(text: str) -> dict` / `send_hint(peer_url, text) -> dict`. Delete the `RULE-27-REMOVE-AT-PRD-4` marker comments and `test_mcp_server.py::test_the_numeric_position_tool_is_gone_once_prd4_lands`'s `xfail` — this is the commit that makes that test start passing for real, and `strict=True` means leaving the marker behind after this would hard-fail the suite, exactly as designed.
- **`memory/scent.py`** — `ScentField`: the cop's own pheromone trail. `emit(pos)` deposits strength `scent_source_strength` (0.9) at the cop's current cell; `decay()` reduces the whole field by `scent_decay_rate` (0.10) per turn; sampling is windowed to `scent_field_size` (5×5) around the cop's current position. Sourced from `GameConfig`, never a literal (I6). See Design Question 1 for what this field actually represents and why.
- **`memory/belief.py`** — `BeliefMap`: a genuine probability distribution over board cells representing where the cop believes the thief is. Starts uniform — deliberately not seeded from `config.thief_start`, see Design Question 2. Updates from two independent inputs: the scent field (down-weights cells the cop has itself recently searched) and the interpreted incoming hint (shifts mass toward the hinted region). Always renormalizes to sum to 1.
- **`tools/hint_providers.py`** — the `[trash_talk] provider` abstraction (Table 21): `template` (default, zero tokens, fully implemented), `ollama` (zero API tokens, implemented as a plain HTTP call to `localhost:11434`), `claude_api`/`claude_cli` (interface present, **not** implemented yet — see Design Question 6). Selected via a new **private**, non-negotiated config file (Table 21/22's own framing), not `config/shared/`. Table 14 #2 is explicit that `hint_word_limit` "applies to template mode and to the LLM (**stated in its system prompt**)" — `OllamaHintProvider`'s prompt construction states the limit as an instruction to the model, not just a post-hoc Python truncation of its output (`reasoning/hint.py`'s own backstop enforcement still applies on top — never trust one enforcement layer for a fatal rule).
- **`reasoning/hint.py`** — two responsibilities, kept in one small module because they're two halves of the same turn: (a) **generate** the outgoing hint — decide the `Intent` flag (true/lie), call the configured provider, enforce `hint_word_limit` (15), feed `arena` ("New York") for landmark flavor; (b) **interpret** an incoming hint into a belief-map-usable directional/regional signal. Rule 25's "text processing and behavioural profiling only" boundary lives here: this module can call an LLM, but the actual belief update and move decision stay pure Python, unchanged from PRD 3.
- **`shared/private_config.py`** — loads the private, per-team `[trash_talk]` block (`provider`, `every_n_steps`). Deliberately separate from `GameConfig`: Table 21/22 are explicit that this config is "private per peer, not negotiated" — never compared for byte-identity against the opponent's copy, unlike everything `GameConfig` already holds.
- **`shared/config.py`** extended with `arena`, `hint_word_limit`, `scent_source_strength`, `scent_decay_rate`, `scent_field_size` — all 31 Appendix F fields are already in `config_dev_g01.json` and already checked by `check_config.py`; only 16 of them have been read into `GameConfig` by code so far, becoming 21 after this layer. The remaining 10 (`sub_games_per_series`, `diversity_reward`, `min_games_to_pass`, `token_estimate_per_series`, `max_games_per_team`, `requests_per_minute`, `parallel_requests`, `retry_delay_seconds`, `retries`, `queue_depth`) are PRD 7's territory.
- **`Orchestrator`/`orchestrator_turn.py`** rewired: `take_turn()` generates a hint (not a `(col, row)` pair) and sends it via `send_hint`; the *outgoing* wire payload is natural language for the first time in this project. `receive_hint` feeds incoming text into belief-map interpretation. The move itself is still decided by `CopBrain` exactly as PRD 3 built it — only what crosses the wire, and what feeds `target_pos`, changes.
- **PRD 3's seam pays off, partially — see Design Question 3 for the precise, honest accounting of what changes and what deliberately doesn't.**

## Milestone

A known-false hint (`Intent = False`) measurably shifts `BeliefMap`'s probability mass toward the *wrong* region relative to the cop's actual position, while `ScentField`'s decay proceeds correctly underneath it — the two channels are observably independent, proving the deception channel is actually exercised, not just present. Proven **locally** (no network, no `Orchestrator`), the same split PRD 3 established: algorithm/reasoning correctness stays offline, wiring correctness is a separate, smaller proof. A second, small test confirms `Orchestrator.take_turn()` sends a real natural-language string over one live localhost round-trip and `receive_hint` decodes it — proving the wire itself is language now, not proving belief-update correctness (Design Question 4).

## Design questions answered here (not left for code-time guessing)

**1. What does "scent" actually represent, given the wire only ever carries free natural language (rule 26/27)?** ~~Not a channel to the opponent — `ScentField` is the cop's own private trail of *where it has already searched*, decaying over time, never transmitted.~~ **Superseded in Revision 1 — see below.** This was a defensible-looking resolution to a real ambiguity in the source material at the time, kept here struck through rather than deleted so the reasoning trail stays honest: `PLAN.md`'s "the scent field, which cannot be faked" was read as a signal the cop senses *about itself*, on the theory that nothing on the wire could carry opponent-scent data without becoming a second numeric-position channel (rule 27). A direct read of ch. 4.2–4.4 (not just PLAN.md's paraphrase) shows the book resolves this the other way — each side reads its *opponent's* scent field — and Revision 1 below works out how to do that without reopening rule 27.

*(Design Question 1 is superseded — this paragraph is preserved for history. See "Revision 1" at the end of this document for the current answer, the down-weighting-own-search-cells half of the original mechanism still stands unchanged.)*

**2. What seeds `BeliefMap` at turn 0, given the cop has no observations yet?** Uniform over all board cells is the honest "I have no information" prior and is trivially a valid probability distribution. It is tempting to seed it from `config.thief_start` (still visible in the shared config) — that would be a second, quieter instance of the PRD 2/3 pattern (legal scaffolding that looks like cheating if it survives). `BeliefMap` starts uniform; `config.thief_start` is not read by anything in `memory/` or `reasoning/hint.py`.

**3. What exactly happens to the PRD 3 seam, and is the "one call site" promise still true?** Not true, and this was found the hard way — by writing the precise test, not by re-reading the design on paper. `run_local_subgame` (PRD 3's algorithm-correctness sandbox) is **not** rewired — it deliberately keeps testing `CopBrain` against perfect information, which is its whole purpose (PRD 3 Design Question 3); its two `ground_truth_target_position(...)` call sites are untouched. On the belief-driven side, it turns out there are also *two* sites, mirroring `subgame.py`'s own init+refresh shape rather than PRD 3's optimistic "one call site": `Orchestrator.__init__` sets `target_pos`'s initial value from `self.belief_map.most_likely_cell()`, and `orchestrator_turn.py`'s `take_turn()` refreshes it again every turn after the belief map updates from the cop's own move (`self.game_state.target_pos = self.belief_map.most_likely_cell()`) — the original TODO4 draft only accounted for the first site and missed the second until `tests/unit/test_prd4_seam.py` itself caught the gap. Both are a real signature change (a `Position` argument becomes a `BeliefMap` object), not the "one-line" swap PRD 3's docstring optimistically promised. `tests/unit/test_prd4_seam.py` asserts all three sites precisely: `subgame.py`'s two sites still call `ground_truth_target_position` (still correct, still ground truth, by design); `orchestrator.py`'s and `orchestrator_turn.py`'s one site each do not; and no other file in `src/` has grown an unaccounted-for fourth site — positive assertions that the swap happened everywhere it needed to, not just a check that stopped failing by accident.

**4. Why split the milestone into a local proof and a separate wire proof, again?** Same reasoning as PRD 3 Design Question 3, reapplied: `PLAN.md`'s own milestone language is about the belief map and scent field's behavior, not about a network round-trip. Coupling every belief-update test to a live `subprocess.Popen` peer would make a `BeliefMap` bug and a networking hiccup look identical in a failing test — exactly the risk already avoided once. `reasoning/hint.py`'s interpretation step and `memory/belief.py`'s update step are pure functions over text/positions; they don't need a peer to be correct.

**5. How is "no coordinates survive anywhere in the outgoing hint" actually checked, given a human reviewer "trust the code" isn't good enough here?** `PLAN.md`'s own instruction is explicit: "grep the wire, do not trust inspection." A test generates a range of hints (`template` mode, both `Intent=True` and `Intent=False`, across many fixed-seed randomized true positions — the same sweep style the PRD 3 review pass used) and greps every one for integer-pair patterns resembling `(col, row)`. The `text` field's string value is exactly what gets JSON-serialized onto the wire byte-for-byte (escaping doesn't change digit sequences), so grepping the generated string *is* grepping the wire — intercepting raw HTTP/JSON bytes at the transport layer would add real engineering complexity without adding certainty over checking the string systematically. The genuinely stronger, unbeatable guarantee — that no numeric position parameter can reach the wire *at all* — comes from removing `receive_position`/`send_position`'s tool signatures entirely (the Build section's first bullet): that's a fact about the MCP schema itself, which no grep is needed to prove.

**6. Why are `claude_api`/`claude_cli` interface-only, not fully implemented?** Table 19's token-bucket rate limiter (rule 28) and the `ApiGatekeeper` pattern (`PLAN.md` §4) exist specifically to prevent a real paid API from 429-blocking or burning budget — and `policy/gatekeeper.py` is explicitly PRD 7's build item, not built yet. Wiring a live, unrated-limited Anthropic API call in a layer two PRDs before its own safety net exists is the kind of scaffolding this project has repeatedly found dangerous to leave lying around (rule 27's own carve-out being the running example). `template` and `ollama` cover the milestone entirely at zero cost (Table 21's own framing: "the entire 6-sub-game series can be played at zero tokens"); `claude_api`/`claude_cli` get a real, selectable interface (so `[trash_talk] provider` config validation doesn't need to special-case them) that raises `NotImplementedError` with a message pointing at this paragraph, closed out once PRD 7's Gatekeeper exists to protect them.

**7. Where does the private config live, and how is it kept separate from the negotiated one?** `config/private/` (new directory, sibling to `config/shared/`), loaded by a new `shared/private_config.py` — deliberately a different loader than `GameConfig.from_file`, so nothing accidentally folds a private, non-negotiated value into the object that `check_config.py --identical` compares between peers. Only `[trash_talk] provider` and `every_n_steps` are read this layer; `[strategy] police_class`/`thief_class` stay out per the "Explicitly out of scope" note above.

The "five mandatory rules" text attached to Tables 21/22 says these values must be "identical between the two teams" and "cryptographically lock[ed]" — worth resolving explicitly, since read too literally that contradicts "private per peer, not negotiated" from the same tables. The consistent reading, and the one this repo's design commits to: each team locks its *own* private choice before the game starts (a Step-0-style, per-team pre-game declaration — PRD 6 territory), not a cross-team byte-identity check. `config/private/` is never an input to `check_config.py --identical`, and that's intentional, not an oversight of the "identical" wording.

## Revision 1 — book-accurate scent model + opponent-scent corroboration

A direct read of the book (`police_thief_p2p.pdf`, pages 40–46, ch. 4.2–4.4 — not just `PLAN.md`'s paraphrase) surfaced three real deviations from what "Built & verified" above shipped:

1. **Whose scent gets read.** Ch. 4.4 ("Scent-Map Tactics"), read in full: each side samples its *opponent's* scent map and cross-references it against that opponent's verbal hints — a worked numeric example follows (cop's map shows τ=0.81 south-east; thief claims "I moved north"; the quantitative check exposes the lie). `PLAN.md`'s own "corroborate every hint against the scent field, which cannot be faked" and "an agent... can only strengthen the scent where it actually stands, which *helps its opponent*" match this reading exactly. The self-trail-only model "Built & verified" shipped cannot implement this mechanic at all — see Design Question 1's superseded note above.
2. **Emission shape.** Ch. 4.3 + Figure 4 (page 44): a fixed radial 5×5 kernel around the emitting cell — 0.90 centre, 0.62 orthogonal, 0.42 diagonal, 0.20/0.14 at range two, 0.04 at the corners — not the single-cell point deposit `ScentField.emit()` shipped with.
3. **Decay/emission composition.** Ch. 4.3: `τ(t+1) = max(0, (1-ρ)·τ(t) + Δτ)` — decayed history plus this turn's fresh deposit, summed and floored at zero, once per full turn. The shipped `emit()` (overwrite) then `decay()` (multiplies the value just written, in the same step) implemented neither the additive composition nor the correct ordering.

Rule 23 is **[FATAL]** specifically on decay-formula deviation, and PRD 5 is where a real, independently-built opponent first appears — a mismatched model makes every match unplayable at exactly the point it would first matter. Worth fixing before PRD 5, not after.

**Resolving the rule 26/27 tension.** Fix #1 above requires the cop to legally come to possess something about the thief's scent field, and the only legal wire channel is free natural language (rule 26/27, **[FATAL]** on a numeric position protocol) — exactly the channel PRD 4 originally built to close off a numeric carve-out. Raised directly to the project owner rather than resolved unilaterally, given the fatal-rule stakes; their answer:

> Form: natural language, satisfying rule 26 — e.g. "the trail here is strong to the north-east, faint due south, nothing elsewhere." Reuse `interpret_hint`'s existing directional parsing. Scope: only cells inside the opponent's own sampling window (nothing about older history elsewhere on the board). Truthfulness: the scent portion is a **declared-truthful** channel, like the barrier declaration — the Intent flag governs only the tactical (lie-capable) hint, never the scent report. Enforcement: scent readings enter the commit hash at PRD 6.

**Design Question 1, answered again:** `ScentField.advance(pos, board)` (replacing `emit()`+`decay()`) implements the book-accurate radial-kernel, additive, floored-at-zero formula, scaled by `config.scent_source_strength` (Figure 4's numbers are the `source_strength=0.9` case; storing the kernel as a fixed *relative* shape and scaling at construction keeps this genuinely config-driven, I6, rather than hardcoding the illustration's literal numbers). The field still serves its original purpose (down-weighting the cop's own recently-searched cells via `update_from_scent`) *and* now also serves as the honest source for a new outgoing **scent report**: a short, deterministic, always-truthful natural-language clause (never routed through `HintProvider`/`choose_provider`/any LLM — a declared-truthful channel routed through a possibly-nondeterministic model would undermine the one property, "uncorruptible," the whole mechanic depends on) describing the dominant compass direction of residual scent within the sender's own current sampling window. Immediately after a fresh `advance()`, that window is radially symmetric (Figure 4's kernel is symmetric), so any directional lean comes entirely from the sender's own decaying history — "strong to the north-east" genuinely means "I was recently near there," a real signal that requires inference over time rather than a lookup, consistent with rule 27's intent. Reduced to a single dominant quadrant (reusing `_quadrant`'s own north/south × east/west vocabulary) rather than the richer multi-direction/intensity phrasing in the illustrative example, so `interpret_hint`'s existing keyword matcher parses it with zero new parsing code — a documented simplification, not a silently narrowed one.

**Wire change.** `receive_hint(text, scent_report)` / `send_hint(url, text, scent_report)` — one combined round-trip, two natural-language fields, not a new tool pair (half the new surface area of a parallel tool, same rule 26/27 posture either way). Both fields independently capped at the existing `config.hint_word_limit` — no new config field invented.

**Belief update.** `BeliefMap.update_from_scent_report(focal_point, board)` — same multiplicative-reweighting shape as `update_from_hint`, a larger `_SCENT_REPORT_BOOST` constant reflecting its guaranteed truthfulness. Applied sequentially alongside `update_from_hint`, not as a discard/override branch: a lie gets *outweighed* by the truthful corroboration rather than requiring explicit contradiction-detection logic.

**Rules owned, updated:** rule 23's job for this layer is now genuinely complete — the model is not just config-driven but matches Table 16/Figure 4 exactly, ready for PRD 6's cryptographic lock. Rule 26/27's posture is unchanged (still zero numeric structure on the wire, still two natural-language strings).

**Milestone, extended:** the original milestone (a lying claim shifts belief wrong, scent decay proceeds independently underneath) stays as a test proving the tactical-claim channel alone is still corruptible without corroboration. A new, stronger milestone case is added: force `Intent=False` on the claim *and* generate a truthful scent report from the same true position; applying both updates to one `BeliefMap`, the true quadrant now outweighs the lie's quadrant — the actual corroboration mechanic PLAN.md calls "the single largest differentiator in the grade," not implemented until this revision.

**Explicitly out of scope, added:** cryptographic enforcement of scent-report truthfulness — folding the declared reading into the per-turn commit hash so a mismatch at the mutual log audit becomes a rule 19 hash-mismatch technical forfeit — is PRD 6's job. This layer only builds honest-by-construction generation (no Intent flag ever applied to it) and a receiver side that treats it as authoritative for corroboration; PRD 6 adds the teeth.

### Built & verified (Revision 1)

Everything above landed per `TODO4-revision.md`'s §0–§9. Three things worth recording that weren't fully anticipated in the plan:

- **`emit()`+`decay()` had to be replaced outright, not extended.** The old two-method shape (a point-overwrite followed by a separate multiply) implemented neither the additive composition nor the correct ordering of `tau(t+1)=max(0,(1-rho)tau(t)+delta_tau)` — every existing caller (`orchestrator_turn.py`, `test_belief_deception.py`'s decay test) needed updating to the single `advance(pos, board)` call, including the "decay only, no fresh deposit" scenario, which now means "advance somewhere far away" rather than a dedicated decay-only method — a real, deliberate consequence of merging emission and decay into one atomic step per the book's own formula, not an oversight.
- **The corroboration milestone needed board geometry chosen deliberately.** Placing the true position at a board corner (as the original milestone did, `Position(0,0)`) makes it geometrically impossible to demonstrate the trail-direction signal agreeing with the true quadrant — any prior position must lie toward the board's interior, which is the *same* direction a lie about that corner would point. The new milestone test picks a true position two cells clear of every edge specifically so the fresh kernel deposit there is itself perfectly symmetric (no clipping bias), isolating the directional lean entirely to genuine trail history. Documented in the test itself and in `scripts/watch_prd4_language.py`'s live demo, both of which use `Position(2, 2)` rather than a corner for this reason.
- **`rule-auditor` found a real, pre-existing I9 gap.** `_on_hint_received` was applying both belief updates unconditionally, before checking either `text` or `scent_report` actually respected `hint_word_limit` — `receive_hint`'s ack flags an over-limit field to the *sender*, but nothing stopped the *content* from reaching belief state on the receiving side. Pre-existing since the original PRD 4 build (confirmed via `git diff` — Revision 1's `on_hint(text)` → `on_hint(text, scent_report)` change only widened the existing pattern to the new field, it didn't introduce the ordering), but this revision touched that exact code path a second time without fixing it, so fixed here: each field is now gated on its own word count independently before it can update belief, proven with a control-`BeliefMap` comparison (an over-limit field's contribution must be provably zero, not just "the flagged cell's probability looks unchanged" — renormalization from the *other*, still-valid field would perturb that reading regardless).

Both design-level sanity-checks (the Figure 4 kernel sabotaged to a point deposit; the scent report sabotaged to always lie) confirmed their respective tests fail as expected, then were cleanly reverted (`git diff` byte-identical afterward).
